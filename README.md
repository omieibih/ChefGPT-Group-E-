# ChefGPT

ChefGPT is a full-stack AI-powered recipe generator. Users enter the ingredients they already have, an optional budget, their cooking experience level, and any dietary restrictions — and the app returns 3 complete meal suggestions with step-by-step instructions, generated by the LLaMA 3.3 70B model via the Groq API.

---

## Features

- Select cooking experience level (Beginner, Intermediate, Advanced) — instructions are tailored accordingly
- Enter ingredients you have on hand and get 3 AI-generated meal suggestions
- Optional budget input to cap the cost of suggested extra ingredients
- Optional dietary filter (e.g. vegan, gluten-free, dairy-free)
- Save recipes to a personal Favorites list (stored in Firestore, per user)
- Shopping list to track ingredients you need to buy
- Ingredient suggestion assistant on the input page
- User authentication via Firebase (email/password)

---

## Tech Stack

**Frontend:** HTML, CSS, Vanilla JavaScript, Firebase JS SDK

**Backend:** Python, Flask

**AI:** Groq API (LLaMA 3.3 70B)

**Nutrition Data:** Edamam Nutrition Analysis API

**Database & Auth:** Firebase Authentication, Firebase Firestore

## Setup Instructions

### 1. Prerequisites

Make sure Python 3 is installed:

```powershell
py --version
```

If not installed, download from [python.org/downloads](https://python.org/downloads).
> During installation, check **"Add Python to PATH"**.

---

### 2. Clone the Repository

```powershell
git clone https://github.com/Jason520-apple/ChefGPT-Group-E-.git
cd ChefGPT-Group-E-
```

---

### 3. Install Dependencies

```powershell
py -m pip install -r requirements.txt
```

---

### 4. Get Your API Keys

ChefGPT requires three external API keys to run fully.

#### Groq API Key (recipe generation)

1. Go to [console.groq.com](https://console.groq.com)
2. Sign up or log in
3. Navigate to **API Keys** in the sidebar
4. Click **Create API Key** and copy it immediately — it is only shown once

#### Edamam API Key (nutrition lookup)

1. Go to [developer.edamam.com](https://developer.edamam.com)
2. Sign up and create an application under **Nutrition Analysis API**
3. Copy your **App ID** and **App Key** from the dashboard

---

### 5. Set Environment Variables

ChefGPT reads all credentials from environment variables — no keys should ever be written directly in code. Create a `.env` file in the project root (it is already in `.gitignore` and will never be committed):

```
GROQ_API_KEY=your-groq-api-key-here
EDAMAM_APP_ID=your-edamam-app-id-here
EDAMAM_APP_KEY=your-edamam-app-key-here
```

Or set them manually in PowerShell for the current session:

```powershell
$env:GROQ_API_KEY="your-groq-api-key-here"
$env:EDAMAM_APP_ID="your-edamam-app-id-here"
$env:EDAMAM_APP_KEY="your-edamam-app-key-here"
```

> The `.env` file approach is recommended — it persists across sessions and you only have to set it once.

---

### 6. Configure Firebase (Required for Login and Favorites)

#### 6a. Frontend config

Open `static/firebase-config.js` and replace the `firebaseConfig` object with your own from:
- Firebase Console → Project Settings → General → Your Apps → Web App

#### 6b. Backend credentials

The backend needs a Firebase service account to verify user tokens and access Firestore.

**Option 1 — environment variable (recommended, no file on disk):**

```powershell
$env:FIREBASE_SERVICE_ACCOUNT_JSON='{"type":"service_account", ...}'
```

**Option 2 — local key file:**

```powershell
$env:FIREBASE_SERVICE_ACCOUNT_PATH="C:/path/to/serviceAccountKey.json"
```

To get your service account key:
- Firebase Console → Project Settings → Service Accounts → Generate New Private Key

> `serviceAccountKey.json` is in `.gitignore` and must never be committed.

#### 6c. Firebase project checklist (fresh clone)

1. Create a Firebase project (or get access to the team project)
2. Enable **Email/Password** under Authentication → Sign-in methods
3. Create a Firestore database
4. Replace `static/firebase-config.js` with your Web App config
5. Set one of the backend credential env vars above
6. Run the app and verify `/login` works and favorites save to Firestore

---

### 7. Run the App

```powershell
py app.py
```

Then open your browser to:

```
http://localhost:5000
```

#### Full startup sequence (run in order every time):

```powershell
py -m pip install -r requirements.txt
$env:GROQ_API_KEY="your-groq-api-key-here"
$env:EDAMAM_APP_ID="your-edamam-app-id-here"
$env:EDAMAM_APP_KEY="your-edamam-app-key-here"
$env:FIREBASE_SERVICE_ACCOUNT_PATH="path/to/serviceAccountKey.json"
py app.py
```

> If you are using a `.env` file, you only need to run `py app.py` — `python-dotenv` loads the file automatically at startup.

## Usage

1. On the home page, select your cooking experience level
2. Enter the ingredients you have (comma-separated, e.g. `chicken, rice, garlic`)
3. Optionally enter a budget for extra ingredients (e.g. `20`)
4. Optionally enter a dietary restriction (e.g. `vegan`, `gluten-free`)
5. Click **Generate Recipes**
6. Click any meal card to expand it and see full ingredients and instructions
7. Click **Save to Favorites** on any recipe to save it to your account
8. Visit **My Favorites** from the nav bar to view or remove saved recipes

## Security — CWE-798: Use of Hard-Coded Credentials

### The Problem

During development, a common mistake our team encountered was **CWE-798: Use of Hard-Coded Credentials** — placing API keys, Firebase credentials, or other secrets directly inside source code files. For example, writing something like this in Python:

```python
# BAD — never do this
client = Groq(api_key="gsk_abc123realkey...")
APP_ID = "a1b2c3d4"
APP_KEY = "xyz9876secretkey"
```

This is a serious security vulnerability. If any of these files are committed to a public GitHub repository, the credentials are permanently exposed in the git history — even if you delete them in a later commit. Attackers can find leaked keys using automated scanners and use them to rack up API charges or access private data.

### How We Fixed It

All credentials in ChefGPT are loaded exclusively from **environment variables**, never written into code. Each API client reads its key at runtime using `os.getenv()` or `os.environ.get()`:

```python
# GOOD — key is read from the environment, not written in code
client = Groq(api_key=os.environ.get("GROQ_API_KEY"))
APP_ID = os.getenv("EDAMAM_APP_ID")
APP_KEY = os.getenv("EDAMAM_APP_KEY")
```

Environment variables are set either via a local `.env` file (loaded by `python-dotenv` at startup) or directly in the shell session. The `.env` file is listed in `.gitignore`, so it is never committed to the repository.

For Firebase, the service account JSON — which grants admin access to the entire Firebase project — is loaded from either:
- `FIREBASE_SERVICE_ACCOUNT_JSON` (the full JSON as a string, set in the environment)
- `FIREBASE_SERVICE_ACCOUNT_PATH` (a path to a local key file, also gitignored)

This pattern means the repository contains **zero credentials**. A teammate cloning the repo gets a working codebase but must supply their own keys — they can never accidentally inherit or expose someone else's.

### Key Takeaways

- Never commit API keys, passwords, or service account files to git
- Use `.env` files locally and add them to `.gitignore` immediately
- Use environment variables in all code that needs credentials
- If a key is ever accidentally committed, rotate it immediately — deleting the file in a new commit does not remove it from git history
